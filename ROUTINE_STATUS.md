## ⚠️ New auto-publish CI pipeline — needs attention

PR #2 (merged 2026-08-08) also introduced `.github/workflows/publish-drafts.yml` + `scripts/publish_draft.py` — added by a human commit alongside the merge, not by this routine. This workflow triggers automatically on every push to `main` that touches `data/drafts/pending-review-*.json`, and if it succeeds it generates audio, uploads it, and **upserts the lesson straight into Supabase as `status='published'`** — no separate manual step.

It already fired once (run [31248024385](https://github.com/erBhushanPawar/lang-learner/actions/runs/31248024385), on the PR #2 merge commit) and **failed immediately** — almost certainly because `GOOGLE_TTS_API_KEY` and/or `SUPABASE_SERVICE_ROLE_KEY` are not yet set as repo secrets. Verified nothing published: Supabase still shows only a1-01/a1-02, and both draft JSON files are still present on `main` (not removed, which the workflow does on success).

**Implication for future runs:** once those secrets are added, merging a `draft-lessons-*` PR into `main` will auto-publish its contents to Supabase immediately, with no separate human-triggered publish step. This changes the safety model this routine was built around ("PR merge ≠ publish; a human runs audio + publish manually"). Also worth noting: a1-03/04/05 (batch 1, already on `main`) have an **unresolved open question** (see below) — if the secrets get added and something re-touches `data/drafts/pending-review-2026-08-07.json`, it would publish without that question being resolved. A human should confirm whether this auto-publish-on-merge behavior is intended before adding those secrets.
